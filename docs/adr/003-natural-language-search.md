# ADR-003: Natural-language search

Date: 2026-10-02 · Status: accepted

This record keeps the whole path of `/ask`: what was built, how an answer is put together and ranked, what was checked on the live site, what each check showed and what changed because of it. The current behaviour is summarised in the README; the evaluation numbers live in [docs/llm](../llm/README.md).

## Context

A player should be able to describe a game in their own words — "кооператив для двох на Switch до 500 грн", "щось як Hades, але коротше" — and get a short list from the catalog with a reason for each game, plus the catalog filter that was understood. Constraints: Ukrainian first; the site must never fail because of the model; the spending cap is a $5 prepaid balance with no automatic reload; the site's Redis token is read-only, so there is no shared server-side counter.

## Decision

Two calls to Claude Haiku 4.5 (`claude-haiku-4-5`) through the Anthropic SDK — one turns the question into the catalog's own filter, one ranks real candidates and explains each — around a retrieval step that runs on the project's own index. Every step has a deadline and a fallback, and the model can only ever choose among games the catalog found.

### How an answer is put together

1. **Parse** (≈ 1.2–2.5 s, ≈ 2 800 input / 120–150 output tokens). The model returns, under a JSON schema (structured output), the fields of `GameFilter` the catalog understands — platform families, genres (RAWG's 19, given as slugs), game modes, age rating, playtime, years, score minimums, price, discount, free, Ukrainian localisation, made in Ukraine, sort — plus up to three **mood tags** from a fixed list of 48 (`shared/moodTags.ts`; "горор" → `horror`, "затишна" → `relaxing`), a title search if the question names a game, and `interpretation`: one sentence in the question's language. The server then re-checks every value against the live taxonomy and clamps every number; anything unknown is dropped, not trusted.
2. **Retrieve** (≈ 0.2 s). The candidates come from the index of ~3 300 games whenever it can express everything understood — which, with tags, years and playtime as index facets, is almost every question. RAWG is used only for a title search, with a single 4 s attempt; if it is slow, the index answers the rest and the title search is reported as not applied. Up to 40 candidates, in this order:
   - with mood tags: games carrying **every** tag, then games carrying the **most defining** tag (the first one the parse listed), then — only if fewer than 3 so far — games carrying **any** of them; if still fewer than 3, the same filter without tags fills the list;
   - within each group, the filter's sort, by default popularity.
3. **Rerank** (≈ 2.3–5.7 s, ≈ 1 800 input / 220–410 output tokens). The model sees the question, the interpretation and the **first 24** candidates as compact lines — id, name, year, genres, tags, how it is played, average length, all in words. It does not see prices or localisation (the filter already guaranteed them, and showing them is what made it echo them back). It returns up to **8** ids, best fit first, each with a reason of at most 80 characters. The prompt asks for something specific about the game — setting, mechanics, tone, length — written as a friend's recommendation, and forbids repeating the request: no prices, platforms, stores, localisation, player counts already asked for, or schema codes. It carries good examples and the bad one seen live.
4. **Server checks on the ranking.** Ids not among the candidates are discarded. A reason that still contains a price, a platform or store name, or a schema code is dropped (the game stays, without a reason). A line over 80 characters ends at the last whole word with an ellipsis. Interpretation and reasons are plain text with links removed and are never rendered as HTML. If fewer than 3 games survive, or the rerank fails or runs out of time, the answer keeps the catalog order without reasons — it stays a structured answer.
5. **Answer**: `{ mode, interpretation, filter, catalogUrl, items: [{ card, reason }], ignoredFilters, indexStale, indexedOnly, matchedTags, tookMs }`.

### Time, money and abuse

- One deadline per request of 15 s. Parse and retrieval must finish by 12 s so a fallback still has time; the rerank gets 7 s from the end of the parse, never past 14 s. Each call has an 8 s timeout; the Vercel function may run 30 s.
- About $0.007 per ranked answer and $0.0034 when the question stops after the parse. Prompt caching is not used: Haiku 4.5's minimum cacheable prefix (4 096 tokens) is larger than these prompts. Answers are cached for 24 h (degraded ones for 10 min).
- 10 questions a minute and 40 model-backed answers a day per client address (the platform's client header, IPv6 by /64), a per-instance daily ceiling, 200 characters, 4 KB bodies. The hard cap is the prepaid balance.
- **Fallback** (no key, a limit reached, credits exhausted, any parse error, refusal or timeout): the question as a plain search over the index's game names, RAWG only if the index is down; the page says the AI part did not run. Never an error page.

## Consequences

- The model decides what the question means and which of the found games fit best; it never decides what exists. Everything it returns is checked before a visitor sees it.
- The ranking is now the bulk of the time (2–6 s, all of it output tokens for eight reasons). The remaining lever is fewer or shorter reasons, not the prompt.
- Answers cover the index's ~3 300 games unless the question names a title; the page says so with the catalog's own note.
- Recorded answers in fixture mode test the code, not the model; quality is measured only by the evaluation run against the live site, about $0.20 a run.
